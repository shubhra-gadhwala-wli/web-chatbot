# Architecture — local-first RAG voice chatbot v1

Sources: [release scope](/WLI/issues/WLI-10#document-release-scope-v1), [requirements](/WLI/issues/WLI-8#document-requirements-draft), [research](/WLI/issues/WLI-9#document-artifact-review-ee5e8461-4258-42e8-a978-f8030d8769b7). UX design spec was not present in the handoff; UI layout and citation presentation need its owner before visual implementation, while this API design can proceed.

## Verdict and boundaries

The named `.txt` slice is technically feasible on a local developer machine with a downloaded local embedding model and either a configured OpenAI-compatible generation endpoint or a local compatible server. No cloud, hosted vector service, OCR, or STT is needed for that slice. A real answer still requires a reachable generation model; offline operation requires the local endpoint and its model to be installed. The first development gate must exercise two accounts and prove that guessed IDs and crafted citation IDs cannot cross account boundaries.

```text
Chrome UI --same-origin HTTPS/localhost cookie--> Python/FastAPI app
  auth/session | document API | conversation API | grounded-answer service
           |                     |                 |
           +--> SQLite metadata/chunks/messages (account-scoped)
           +--> private local file directory (opaque IDs)
           +--> local ingest worker --> text/PDF extraction --> chunking --> local embeddings --> embedded LanceDB
           +--> configurable OpenAI-compatible chat endpoint (document excerpts leave machine if remote)
Chrome SpeechRecognition/SpeechSynthesis stay in browser; transcript uses ordinary text-chat API.
```

One deployable application plus a bounded worker process share one local data directory. Only the app binds loopback by default. Worker has no HTTP port. SQLite is the authority for ownership, status, canonical extracted text and citation metadata; LanceDB is a disposable derived index. Files and vector directories are private to the OS account running the app. No direct browser access to file or vector paths. Every route derives account ID from the server session, never request input. Every SQL read/update uses `(account_id, id)`; retrieval filters by account and ready document IDs, then rechecks every returned chunk against SQLite before prompt construction or citation response. Conversation, message, document and citation lookups all use the same rule. Unknown and foreign IDs return identical 404s. Persist citations as chunk IDs tied to the answering account; deleted source yields a safe “source removed” display, never another account’s data.

## ADR 1 — Application and storage

**Decision requiring CEO approval:** Python 3.12/FastAPI application, SQLite WAL as local metadata source, LanceDB embedded index, React/TypeScript web UI. Local single-installation multi-user tenancy partitions by account ID in one store. **Why:** Python has mature parsing and local embedding support; SQLite avoids a separately administered database at this scale; embedded vectors meet local-only operation. **Rejected:** Node-only app (local model/PDF pipeline less cohesive), PostgreSQL/pgvector (extra service for a small local install), Chroma persistent client (its own docs prefer server mode for production), FAISS (application must build durable metadata/filtering), Qdrant server (extra exposed service), separate microservices (operational burden). **Consequences:** one writer discipline, WAL/busy timeout, serialized ingest commits, backup must snapshot DB/files/index coherently; local process compromise exposes all accounts. Moving to PostgreSQL or changing tenancy later needs schema/data migration and isolation retest. This one-way door must be escalated to CEO before irreversible implementation.

## ADR 2 — Identity and secrets

**Decision requiring CEO approval:** Argon2id password hashes with per-hash salt and configured memory/time limits; opaque 256-bit random session token in HttpOnly, SameSite=Lax, Secure-on-HTTPS cookie. SQLite stores only SHA-256 token digest, account ID, created/expiry/revoked timestamps. Absolute expiry 14 days, logout revokes; rotate on login and registration. CSRF protection through same-origin Origin/Referer enforcement on state-changing requests plus CSRF token for clients where Origin is absent. Rate-limit login and registration per IP/account locally. Minimum password length 12; reject >1024 bytes. Generic login error. **Rejected:** JWT in localStorage (hard to revoke, XSS exposure), OAuth provider (unavailable vendor/access and extra data flow), plaintext or reversible passwords. **Consequences:** browser sessions expire even during activity at day 14; changing auth scheme requires migration and forced logout. YAML holds non-secret defaults and endpoint URL; `.sample.env` lists secret variable names. Runtime environment overrides secrets; never commit real `.env`, tokens or keys. Optional OpenAI API key applies to chat generation only. Endpoint must be explicitly configured for remote transfer; local endpoint is a supported configuration. Endpoint URL is admin/local configuration, never user-supplied per request, and must reject embedded credentials.

## ADR 3 — Ingestion and retrieval

**Decision:** allow `.txt`, `.md`, text-layer PDF; validate extension, detected MIME/signature and 25 MiB streamed maximum before creating a record. Reject binary-looking text, invalid UTF-8, empty extracted text, encrypted/scanned/corrupt PDF with clear failed reason. Use PyMuPDF in isolated worker with page/text/time bounds; text and Markdown are stored as text, not rendered HTML. Chunk normalized text at about 800 tokens with 120 overlap, retaining page (PDF) or line interval (text) and deterministic sequence. Use pinned `all-MiniLM-L6-v2` locally, 384-dimensional cosine vectors, record model/version per chunk. Use bounded queue, one ingest at a time by default, subprocess timeout and memory cap. **Rejected:** PDF.js server parsing (browser-oriented), Tika (Java service and broad attack surface), Docling (unneeded model footprint), OpenAI embeddings (unnecessary document egress), Ollama embeddings (additional required runtime). Model/index change requires re-embedding from canonical extracted text, with no silent mixed dimensions.

State transition: uploaded -> processing -> ready or failed; delete can be requested in any state. Stage vectors under document generation ID; make ready visible only after SQLite chunk records and index writes complete. Retrieval considers ready only. Worker checks deletion tombstone between stages; deletion blocks future retrieval immediately, cancels/ignores worker result, removes file/text/chunks/vectors idempotently, and finishes record removal. Reconcile incomplete stages at startup; failed documents have no searchable vectors. No in-place retry: delete and upload again. Poll document statuses every 2 seconds while unfinished, taper when idle.

Retrieval embeds the question locally; scoped top-k=5 candidate chunks, minimum calibrated similarity threshold plus ownership/ready recheck. If none, return `no_documents` or `no_relevant_context` without calling the LLM. Prompt contains bounded source excerpts with opaque citation handles and instruction to answer only from them. Parse only handles present in retrieved set; reject unsupported handles, and if answer lacks verifiable supporting citation return `no_relevant_context` (no fabricated answer). Model failure returns retryable 502/504, no assistant answer saved; question may be retained with failed attempt state. User text and document text are untrusted prompt content. A citation identifies document ID/name and chunk ID with page or line range; raw excerpts are resolved through scoped API. Generation is non-streaming. API and UI expose pending state while request runs. Endpoint timeout 60s, cancellation on client disconnect best effort, concurrency limit 2 with 429/Retry-After on saturation.

## Conceptual data and API contract

Accounts own sessions, documents, extracted chunks, conversations, messages and answer citations. Documents have status, original filename, size, timestamps, failure code and generation. Chunks have document/account IDs, ordinal, location, canonical text, embedding model version. Vector rows carry account/document/chunk/generation IDs. Conversations have owner, name, timestamps; messages have role, content, status, ordered sequence; citations connect answer message to chunk/document snapshot identifiers. DataAPI owns physical keys, indexes, migrations and exact schema.

All routes are `/api/v1`, JSON except multipart upload. `POST /auth/register|login`, `POST /auth/logout`, `GET /auth/me`; `POST /documents` (one file, 201 uploaded), `GET /documents`, `GET /documents/{id}`, `DELETE /documents/{id}` (204 idempotent), `GET /documents/{id}/chunks/{chunkId}`; `GET/POST /conversations`, `GET/PATCH /conversations/{id}`, `GET /conversations/{id}/messages`, `POST /conversations/{id}/messages` with `{text,clientRequestId}` and complete response `{message,answer:{kind:answered|no_documents|no_relevant_context,text,citations:[{documentId,documentName,chunkId,location}]}}`. Idempotency: unique `(account_id, clientRequestId)` returns prior result on retry, rejects changed payload; upload uses request ID or content hash scoped to account only to prevent duplicate retry records. 400 validation, 401 unauthenticated, 404 foreign/missing, 409 state conflict, 413 oversize, 415 type, 429 capacity, 502/504 model error. No document bytes or excerpts in logs.

## Local topology, targets and accepted failures

`config.yaml` plus `.sample.env`; developer command initializes private data directory/migrations, starts API and worker, and serves built UI on localhost. Model download is a documented setup step with pinned checksum; local LLM setup is optional configuration. No production infrastructure or cloud deployment. Target reference machine: 4 CPU cores, 8 GiB RAM, SSD, low tens of documents/account, 25 MiB/file, 2 concurrent answer requests. On that machine, target p95 authenticated metadata API <300 ms, `.txt` 1 MiB ingest-to-ready <30 s after model warmup, retrieval <1 s, answer <60 s excluding an independently slow configured model; local app availability 99% while host is running (best-effort target, not user SLA). Bounded 100 pending ingest items, 2 answer slots; reject beyond capacity. Disk budget estimate: original+extracted text up to ~2x source plus roughly 2 KiB/vector chunk and model cache; validate with measured fixtures before release. Hosted generation cost is user/provider-dependent and cannot be quoted without model choice; local generation has no per-call vendor fee but hardware/power cost. Accepted failures: host down means app down; SQLite/database lock can delay writes; local index corruption requires rebuild from chunks; malformed PDF fails ingest; external endpoint outage stops answers but library remains available; browser STT can be unavailable or service-backed. Health checks report worker/index/model readiness separately; structured logs redact content, with request IDs, state transitions, queue depth, ingest duration, retrieval hit/no-context and model error counts. SRE to review thresholds, DevOps to review packaging, SecurityArchitect to approve threat model before design sign-off.

## First-slice interface and sequence

1. SecurityArchitect: threat model of session/CSRF, parser, prompt injection, file path and cross-account IDOR; deliver verdict before sign-off.
2. DataAPI: migration and repository contracts `account_id` scoped CRUD; SQLite and Lance vector adapter; exact API OpenAPI schema from shapes above. Contract to Backend: `createUpload`, `claimIngest`, `commitChunksAndReady`, `failIngest`, `deleteDocument`, `retrieveReadyChunks` are account-scoped/idempotent; return opaque IDs and typed errors.
3. Backend: auth, `.txt` upload/ingest/retrieval/generation route, using DataAPI contract; local run command/config. Acceptance: two real accounts, real local embedding/index, cited answer or no-context, no mocked LLM/retrieval, delete and foreign-ID denial at backend boundary. It can use configured local compatible model for full offline demo.
4. Web: register/login, upload/status, ask/pending/citation/no-context against published OpenAPI; no browser-owned authorization state. Can start after contract draft; integration after Backend route. UX spec owner must resolve visual flows before final UI acceptance.
5. QAFunctional: independent two-account isolation, status transitions, no-context/citation, retry/idempotency and local end-to-end fixtures; findings on its own task. DevOps: local run instructions and environment validation; SRE: telemetry/operability review. PDF/Markdown, full deletion, conversations and voice follow after slice.

Interfaces between tasks are the OpenAPI document (DataAPI -> Backend/Web/QA), scoped repository interface (DataAPI -> Backend), and JSON state/citation schema (Backend -> Web/QA). No task may infer ownership from a client-supplied account ID.
